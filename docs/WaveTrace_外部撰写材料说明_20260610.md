# WaveTrace 外部撰写材料说明

日期：2026-06-10  
用途：给专利代理人、技术文档作者或外部工程顾问理解系统，不要求对方直接读完全部 C++ 代码。

## 1. 写材料时的总原则

这套系统的价值不在某一个变量名、函数名或文件名，而在三个技术构思：

1. 用反射式机制把普通业务对象自动转成可追踪波形拓扑。
2. 用波形语义压缩和二维分块索引替代 VCD 文本事件流。
3. 用查看器按需加载和层级概要显示支撑十 GB 级大文件交互。

写专利或技术材料时，应强调“原理、结构、流程、效果”，弱化具体代码实现。不要把内部实现名照抄到正文里，除非它们已经是行业通用词，例如 VCD、SystemC、LOD、Zstd。

## 3. 推荐拆成三项技术主题

### 3.1 主题一：反射式通用波形追踪系统

适合强调：

- 芯片架构仿真中，真实状态不只存在于标准信号对象，还存在于普通 C++ 业务对象、嵌套结构、数组、队列、端口、位段、联合体等。
- 传统 SystemC 波形机制更依赖显式注册标准信号，难以自然覆盖业务对象语义。
- 本系统通过反射信息自动展开对象结构，形成稳定波形拓扑。
- 运行期只按拓扑采样变化，避免每周期重复解析结构。
- 位段和联合体采用“逻辑视图 + 物理存储”分离，既保持业务字段名称，又避免重复保存底层数据。
- 指针、端口、别名对象采用受控展开，避免重复追踪和递归展开。
- 通过主动变更提示、连续内存预比较、平坦采样表和并行采样支撑百万级信号。
- 通过追踪层级限制控制自动展开深度。

应避免：

- 不要把重点写成“生成某某 C++ 模板代码”。
- 不要过度描述 `TrackId`、`NodeId` 等变量名。
- 不要把 WVZ4 文件压缩细节写成本主题核心。

可用标题：

```text
面向芯片架构仿真的反射式通用波形追踪方法及系统
```

### 3.2 主题二：WVZ 波形语义压缩与分块索引

适合强调：

- VCD 虽然保存 value change，但每条事件仍然是文本表达，包含时间文本、值文本和信号标识重复。
- 仅把 VCD gzip 压缩不是根本改变数据表达。
- 本系统把拓扑和动态样本分离，动态区只保存真正变化的信息。
- 默认初值、前值去重、局部时间编码、共享时间表、固定宽数值、信号局部记录等属于波形语义压缩。
- 时间块 × 信号块的二维分块，使文件天然支持局部读取。
- 稀疏/稠密表达按块选择，适应不同变化密度。
- 一位信号可按翻转序列表达，多字节值可按变化字节表达。
- 多个逻辑视图共享同一物理存储流，避免 bitfield/union 重复保存。
- 语义减量后再使用通用无损压缩。
- 文件尾索引支持按时间和信号定位数据块。

应避免：

- 不要把 Viewer 的界面、搜索、跳转作为本主题重点。
- 不要把 LOD 强塞进压缩专利正文；如果写，也只能作为文件内可选概要，不作为 Viewer 交互。
- 不要宣称“VCD 不保存变化”。正确说法是：VCD 已保存变化，但变化事件内部仍存在文本和上下文冗余。

可用标题：

```text
面向大规模仿真波形的多重语义压缩及分块索引方法
```

### 3.3 主题三：大规模波形查看器按需加载与层级概要

适合强调：

- 十 GB 级波形文件不能打开时全量解析，否则时间和内存都不可接受。
- 查看器打开阶段只读取目录、信号拓扑、块索引和概要索引。
- 根据活动信号和可见时间窗口计算命中数据块，未命中块不读、不解压、不解析。
- 远距离显示时使用层级概要，近距离或精确操作时回到原始变化样本。
- 概要窗口必须记录尾锚点，即窗口内最后一次变化，保证后续稳定区状态正确。
- 概要规模按层级和来源记录数量控制，避免概要本身膨胀。
- 数值搜索只针对选中/高亮信号执行，统计各信号命中并跳到首个结果。
- 双文件对比先用拓扑匹配和概要定位候选差异，再用原始样本确认。
- bitfield/union 等逻辑信号在查看器中按位范围从底层存储读取。

应避免：

- 不要把 LOD 描述成会替代原始数据。它只是远景显示和候选定位的加速结构。
- 不要说搜索必须全文件全信号扫描。该系统的方向是选中信号 + 按需数据块。
- 不要把 UI 按钮、Qt 类名作为创新点。

可用标题：

```text
面向大规模波形文件的按需加载、层级概要显示与交互分析方法及系统
```

## 4. 关键技术关系图

```text
业务对象
  -> 反射式拓扑生成
  -> 逻辑信号 / 物理存储关系
  -> 周期变化采样
  -> WVZ 语义压缩
  -> 时间块 × 信号块
  -> 文件尾索引 + 层级概要
  -> 查看器按需加载
  -> 搜索 / 显示 / 对比
```

反射追踪、WVZ 压缩、Viewer 不是完全割裂的三件事，它们共享一个核心思想：大规模波形不能靠“全量展开、全量扫描、全量显示”，必须把稳定结构、动态变化、局部访问和用户可见范围分开处理。

## 5. 重要正确性点

### 5.1 LOD 尾锚点

波形值具有延续性：某个时间之后的值由之前最后一次变化决定。因此概要窗口里记录“第一处变化”不够安全。必须记录窗口内最后一次变化，才能保证后续稳定区显示正确。

这点适合写成 Viewer 专利中的核心正确性机制。

### 5.2 位段/联合体不重复保存

位段和联合体的多个业务字段可能共享同一底层字节。正确做法是：

```text
业务字段作为逻辑信号展示
底层数据作为物理存储保存一次
逻辑信号通过位范围引用底层数据
```

这点同时属于反射追踪和 WVZ 压缩的交叉价值。

### 5.3 helper 进程恢复边界

辅助写入进程不是魔法恢复。它只能 finalize 已经收到的完整周期。还在主进程内存里的当前周期、半个 pipe frame、未发送数据都不能恢复。

写材料时应说“提高异常退出后的已提交数据可用性”，不要说“保证任何 crash 后数据完全不丢”。

### 5.4 精确取值以原始样本为准

Viewer 远景可以用 LOD；但光标精确值、导出、最终搜索确认、最终对比确认应使用原始变化样本或无损恢复结果。

这样写能避免被质疑 LOD 近似造成错误。

## 7. 写材料时不要这样写

不要写：

```text
本发明通过 storage_id、rawBits、FOOT、WDAT、LODZ、TrackEvent 等字段实现。
```

应该写：

```text
本发明将用户可见的逻辑信号与实际保存的物理存储流分离，并在文件尾建立数据块索引，使读取端能够按时间范围和信号范围定位必要数据。
```

不要写：

```text
Viewer 调用 WaveParser4::loadFromFile 并设置 autoLoadFirstSignalCount。
```

应该写：

```text
查看器打开文件时只读取目录、拓扑和索引；当用户选择信号或移动时间窗口时，再按需加载对应数据块。
```

不要写：

```text
使用线程池、vector、unordered_map 优化。
```

应该写：

```text
在拓扑稳定后，将采样任务平坦化并按连续区间分配给多个工作单元，减少运行期树遍历和动态查找开销。
```

## 8. 建议交付给外部作者的材料顺序

1. 先读 `docs/WaveTrace_完整技术交接文档_20260610.md`。
2. 再读本文件。
3. 对照代码只看关键文件，不要从 `.sln` 或历史 changelog 开始。
4. 如果写专利，先确定三件主题边界，再分别写现有技术、问题、方案、效果。
5. 代码变量名只作为内部理解辅助，不进入正式正文。

## 9. 需要作者主动追问的点

外部作者如果要写正式专利，建议追问：

1. 实际业务模型中最典型的对象结构是什么，例如 cache、fifo、transaction、port、scoreboard。
2. 最终对标的是 SystemC trace、VCD、FSDB，还是内部已有工具。
3. 是否有实测文件大小、打开时间、内存占用、采样吞吐数据。
4. 是否需要把 helper 进程抗 kill 单独写入压缩专利或作为附属权利要求。
5. LOD 是最终放进 Viewer 专利，还是作为 WVZ 文件可选概要在压缩专利中只轻描淡写。
6. FIFO/队列统一追踪是否已经成为当前实现的一部分，还是后续规划。

## 10. 最终建议

如果只追三件核心价值，建议排序如下：

1. 反射式通用波形追踪：系统入口价值最高，区别于 SystemC trace 最明显。
2. WVZ 语义压缩和分块索引：文件体积与读写性能价值明确，适合与 VCD/gzip VCD 对比。
3. Viewer 按需加载和 LOD：用户体验最直观，适合用十 GB 文件、远景缩放、搜索和对比说明效果。
